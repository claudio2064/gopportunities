Para fazer um commit e enviar suas alterações para o GitHub pelo Visual Studio Code, você pode usar a aba Controle do Código-Fonte (Source Control) sem precisar digitar comandos no terminal.

Pré-requisitos

Antes de começar, garanta que o ambiente esteja pronto:
• Git instalado. O Git precisa estar instalado no seu computador para que o editor reconheça o controle de versão.
• Repositório vinculado. A pasta do projeto deve estar conectada ao seu repositório no GitHub e você deve estar logado na sua conta pelo VS Code.

Passo a passo pela interface visual

1. Abra a aba de Controle do Código-Fonte. Clique no ícone de ramificação (três bolinhas conectadas) na barra lateral esquerda ou pressione Ctrl + Shift + G.
2. Prepare os arquivos (Stage). Passe o mouse sobre a seção Alterações (Changes) e clique no ícone + para preparar todos os arquivos modificados. Se preferir enviar apenas arquivos específicos, clique no + ao lado de cada item desejado.
3. Escreva a mensagem do commit. Na caixa de texto acima do botão de confirmação, digite uma descrição clara e curta do que você alterou no código.
4. Confirme e envie (Commit & Push). Clique na setinha ao lado do botão azul Confirmar (Commit) e selecione Confirmar e Enviar por Push (Commit & Push). Se você clicar apenas em Confirmar, o botão mudará para Sincronizar Alterações (Sync Changes), que também envia tudo para o GitHub.

Aqui está o passo a passo para resolver isso no Windows:

1. Instalar um compilador C (GCC)
O jeito mais fácil no Windows é usar o MSYS2 ou o MinGW-w64 para obter o gcc .

Opção A (MSYS2 - Recomendado):

Baixe e instale o MSYS2.
Abra o terminal do MSYS2 e instale o compilador com o comando: pacman -S mingw-w64-ucrt-x86_64-gcc .
Adicione a pasta bin do GCC ao PATH do Windows (geralmente C:\msys64\ucrt64\bin) .
Opção B (MinGW-w64 direto):

Baixe uma versão do MinGW-w64 (ex: de sourceforge ou winlibs).
Extraia em um local como C:\mingw64.
Adicione C:\mingw64\bin às variáveis de ambiente do sistema (PATH) .
2. Verificar se o GCC está acessível
Abra um novo terminal (PowerShell ou CMD) e digite:

powershell
gcc --version
Se aparecer a versão do GCC (ex: gcc (x86_64-win32-seh-rev1...) 13.1.0), está tudo certo .

3. Habilitar o CGO
Ainda no terminal, configure o Go para habilitar o CGO de forma permanente:

go env -w CGO_ENABLED=1
Você pode verificar se funcionou rodando go env CGO_ENABLED. Deve retornar 1 .

4. Rodar o projeto novamente
Agora que o compilador está no PATH e o CGO está ligado, execute o seu código:

powershell

(Se ainda der erro, tente rodar go clean -cache antes para limpar o cache de compilação e depois go run novamente.)

💡 Alternativa (Sem instalar nada)
Se você não quiser instalar o GCC no seu Windows, existe uma alternativa: trocar o driver do SQLite por um que seja puramente Go (não precisa de CGO).
Você pode usar o driver modernc.org/sqlite no lugar do github.com/mattn/go-sqlite3. No seu código, a importação mudaria de _ "github.com/mattn/go-sqlite3" para _ "modernc.org/sqlite", e o nome do driver na string de conexão (sql.Open) mudaria de "sqlite3" para "sqlite" . Isso simplifica o deploy, mas exige alterar o código.

Meu codigo do sqlite foi estruturado assim 
package config

import (
	"os"

	"github.com/claudio2064/gopportunities.git/schemas"
	"gorm.io/driver/sqlite"
	"gorm.io/gorm"
)

func InitializeSQLite() (*gorm.DB, error) {
	logger := GetLogger("sqlite")

	dbPath := "./db/main.db"
	// Chec if the data file exists
	_, err := os.Stat(dbPath)
	if os.IsNotExist(err) {
		logger.Info("database file not found, creating....")
		err = os.MkdirAll("./db", os.ModePerm)
		if err !=nil {
			return nil, err
		}
		file, err := os.Create(dbPath)
		if err !=nil {
			return nil, err
		}
		file.Close()
	}

	db, err := gorm.Open(sqlite.Open(dbPath), &gorm.Config{})
	if err != nil {
		logger.Errorf("sqlite opening error: %v", err)
		return nil, err
	}

	// Migrate the Schemas
	err = db.AutoMigrate(&schemas.Opening{})
	if err != nil {
		logger.Errorf("sqlite automigration error: %v", err)
		return nil, err
	}

	//Return the DB
	return db, nil
}
